# StatelessWidget vs StatefulWidget 첫 만남

Flitter에는 두 가지 주요 위젯 타입이 있습니다: **StatelessWidget**과 **StatefulWidget**. 이 둘의 차이를 이해하는 것은 Flitter 개발의 핵심입니다. 언제 어떤 위젯을 사용해야 할까요?

## 이 튜토리얼에서 배울 것

- [ ] StatelessWidget의 개념과 사용법
- [ ] StatefulWidget의 개념과 생명주기
- [ ] 상태(State)의 의미와 setState() 사용법
- [ ] 두 위젯 타입을 선택하는 기준
- [ ] 실제 예제를 통한 비교

## StatelessWidget - 변하지 않는 UI

StatelessWidget은 한 번 생성되면 변하지 않는 위젯입니다. 외부에서 받은 props만을 사용해 UI를 그립니다.

### 기본 구조
```typescript
class _MyStatelessWidget extends StatelessWidget {
  constructor(props) {
    super(props);
    // props 저장
    this.title = props.title;
    this.color = props.color;
  }
  
  build(context) {
    // props를 사용해 UI 구성
    return Container({
      color: this.color,
      child: Text(this.title)
    });
  }
}
```

### 특징
1. **불변성**: 한 번 생성되면 변경 불가
2. **단순함**: 상태 관리가 필요 없어 간단
3. **예측 가능**: 같은 props면 항상 같은 UI
4. **성능**: 상태 변경이 없어 효율적

> **💡 핵심 개념: Props vs State**
> 
> - **Props**: 부모에서 전달받는 읽기 전용 데이터
> - **State**: 위젯이 직접 관리하는 변경 가능한 데이터
> 
> StatelessWidget은 Props만 사용하고, StatefulWidget은 둘 다 사용할 수 있습니다.

### 언제 사용할까?
- 정적인 UI 요소 (로고, 아이콘, 레이블)
- 외부 데이터만 표시하는 경우
- 사용자 상호작용이 없는 경우
- 단순한 레이아웃 구성

## StatefulWidget - 동적인 UI

StatefulWidget은 변경 가능한 상태를 가지며, 상태가 변경되면 UI가 자동으로 업데이트됩니다.

### 기본 구조
```typescript
// 1. StatefulWidget 클래스
class _MyStatefulWidget extends StatefulWidget {
  constructor(props) {
    super(props);
    this.initialValue = props.initialValue;
  }
  
  createState() {
    return new _MyStatefulWidgetState();
  }
}

// 2. State 클래스
class _MyStatefulWidgetState extends State {
  // 상태 변수
  count = 0;
  
  // 초기화
  initState() {
    super.initState();
    this.count = this.widget.initialValue || 0;
  }
  
  // UI 구성
  build(context) {
    return GestureDetector({
      onClick: () => {
        // setState로 상태 변경
        this.setState(() => {
          this.count++;
        });
      },
      child: Text(`Count: ${this.count}`)
    });
  }
}
```

### 특징
1. **가변성**: setState()로 상태 변경 가능
2. **반응성**: 상태 변경 시 자동으로 rebuild
3. **생명주기**: initState, dispose 등 생명주기 메서드
4. **복잡도**: 상태 관리로 인한 복잡성

### 언제 사용할까?
- 사용자 입력을 처리하는 경우 (폼, 버튼)
- 애니메이션이 필요한 경우
- 실시간 데이터를 표시하는 경우
- UI가 동적으로 변하는 경우

## setState() 이해하기

`setState()`는 StatefulWidget의 핵심입니다. 상태를 변경하고 UI를 다시 그리도록 합니다.

### 올바른 사용법
```typescript
// ✅ 좋은 예: setState 내에서 상태 변경
this.setState(() => {
  this.count++;
  this.isActive = true;
});

// ❌ 나쁜 예: setState 밖에서 상태 변경
this.count++;  // UI가 업데이트되지 않음!
this.setState(() => {});
```

### setState() 동작 과정
1. setState() 호출
2. 콜백 함수 실행 (상태 변경)
3. 위젯 다시 빌드 예약
4. build() 메서드 재실행
5. UI 업데이트

```typescript
class _InteractiveCard extends StatefulWidget {
  createState() {
    return new _InteractiveCardState();
  }
}

class _InteractiveCardState extends State {
  isExpanded = false;
  isFavorite = false;
  
  build(context) {
    return GestureDetector({
      onClick: () => {
        this.setState(() => {
          this.isExpanded = !this.isExpanded;
        });
      },
      child: Container({
        height: this.isExpanded ? 200 : 100,
        child: Column({
          children: [
            // 기본 콘텐츠
            Text("클릭하여 확장"),
            
            // 확장 시 추가 콘텐츠
            if (this.isExpanded) ...[
              Text("추가 정보"),
              IconButton({
                icon: this.isFavorite ? "❤️" : "🤍",
                onPressed: () => {
                  this.setState(() => {
                    this.isFavorite = !this.isFavorite;
                  });
                }
              })
            ]
          ]
        })
      })
    });
  }
}
```

## 선택 가이드

### StatelessWidget을 선택하세요:
- ✅ UI가 props에만 의존하는 경우
- ✅ 사용자 상호작용이 없는 경우
- ✅ 시간에 따라 변하지 않는 경우
- ✅ 단순한 표시 목적인 경우

### StatefulWidget을 선택하세요:
- ✅ 사용자 입력을 처리해야 하는 경우
- ✅ 시간에 따라 변하는 데이터가 있는 경우
- ✅ 애니메이션이 필요한 경우
- ✅ 로컬 상태 관리가 필요한 경우

## 성능 고려사항

### StatelessWidget
- 불필요한 rebuild 없음
- const 생성자 활용 가능
- 메모리 효율적

### StatefulWidget  
- setState() 호출 시 전체 rebuild
- 상태 관리 오버헤드
- 필요한 경우에만 사용

## 마이그레이션 팁

처음에는 StatelessWidget으로 시작하고, 상태가 필요해지면 StatefulWidget으로 변환하세요:

```typescript
// 1단계: StatelessWidget으로 시작
class _MyWidget extends StatelessWidget {
  build(context) {
    return Text("정적 텍스트");
  }
}

// 2단계: 상태가 필요해지면 변환
class _MyWidget extends StatefulWidget {
  createState() => new _MyWidgetState();
}

class _MyWidgetState extends State {
  text = "동적 텍스트";
  
  build(context) {
    return GestureDetector({
      onClick: () => {
        this.setState(() => {
          this.text = "변경됨!";
        });
      },
      child: Text(this.text)
    });
  }
}
```
