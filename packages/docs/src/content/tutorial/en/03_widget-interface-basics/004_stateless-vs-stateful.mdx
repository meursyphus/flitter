# First Look at StatelessWidget vs StatefulWidget

Flitter has two main widget types: **StatelessWidget** and **StatefulWidget**. Understanding the difference between these two is core to Flitter development. When should you use which widget?

## What You'll Learn

- [ ] The concept and usage of StatelessWidget
- [ ] The concept and lifecycle of StatefulWidget
- [ ] The meaning of state and using setState()
- [ ] Criteria for choosing between the two widget types
- [ ] Comparison through practical examples

## StatelessWidget - Unchanging UI

StatelessWidget is a widget that doesn't change once created. It uses only external props to draw the UI.

### Basic Structure
```typescript
class _MyStatelessWidget extends StatelessWidget {
  constructor(props) {
    super(props);
    // Store props
    this.title = props.title;
    this.color = props.color;
  }
  
  build(context) {
    // Compose UI using props
    return Container({
      color: this.color,
      child: Text(this.title)
    });
  }
}
```

### Characteristics
1. **Immutability**: Cannot change once created
2. **Simplicity**: Simple without state management
3. **Predictability**: Same props always produce same UI
4. **Performance**: Efficient with no state changes

> **💡 Core Concept: Props vs State**
> 
> - **Props**: Read-only data passed from parent
> - **State**: Mutable data managed directly by the widget
> 
> StatelessWidget uses only Props, while StatefulWidget can use both.

### When to Use?
- Static UI elements (logos, icons, labels)
- When only displaying external data
- When there's no user interaction
- Simple layout composition

## StatefulWidget - Dynamic UI

StatefulWidget has mutable state, and when state changes, the UI updates automatically.

### Basic Structure
```typescript
// 1. StatefulWidget class
class _MyStatefulWidget extends StatefulWidget {
  constructor(props) {
    super(props);
    this.initialValue = props.initialValue;
  }
  
  createState() {
    return new _MyStatefulWidgetState();
  }
}

// 2. State class
class _MyStatefulWidgetState extends State {
  // State variables
  count = 0;
  
  // Initialization
  initState() {
    super.initState();
    this.count = this.widget.initialValue || 0;
  }
  
  // UI composition
  build(context) {
    return GestureDetector({
      onClick: () => {
        // Change state with setState
        this.setState(() => {
          this.count++;
        });
      },
      child: Text(`Count: ${this.count}`)
    });
  }
}
```

### Characteristics
1. **Mutability**: Can change state with setState()
2. **Reactivity**: Automatically rebuilds when state changes
3. **Lifecycle**: Lifecycle methods like initState, dispose
4. **Complexity**: Complexity from state management

### When to Use?
- Processing user input (forms, buttons)
- When animations are needed
- Displaying real-time data
- When UI changes dynamically

## Understanding setState()

`setState()` is the core of StatefulWidget. It changes state and triggers UI redraw.

### Correct Usage
```typescript
// ✅ Good: Change state inside setState
this.setState(() => {
  this.count++;
  this.isActive = true;
});

// ❌ Bad: Change state outside setState
this.count++;  // UI won't update!
this.setState(() => {});
```

### How setState() Works
1. Call setState()
2. Execute callback function (change state)
3. Schedule widget rebuild
4. Re-execute build() method
5. Update UI

## Real Comparison Examples

### Static Card (StatelessWidget)
```typescript
class _ProductCard extends StatelessWidget {
  constructor({ name, price, image }) {
    super();
    this.name = name;
    this.price = price;
    this.image = image;
  }
  
  build(context) {
    return Container({
      child: Column({
        children: [
          Image({ src: this.image }),
          Text(this.name),
          Text(`$${this.price}`)
        ]
      })
    });
  }
}
```

### Dynamic Card (StatefulWidget)
```typescript
class _InteractiveCard extends StatefulWidget {
  createState() {
    return new _InteractiveCardState();
  }
}

class _InteractiveCardState extends State {
  isExpanded = false;
  isFavorite = false;
  
  build(context) {
    return GestureDetector({
      onClick: () => {
        this.setState(() => {
          this.isExpanded = !this.isExpanded;
        });
      },
      child: Container({
        height: this.isExpanded ? 200 : 100,
        child: Column({
          children: [
            // Basic content
            Text("Click to expand"),
            
            // Additional content when expanded
            if (this.isExpanded) ...[
              Text("Additional info"),
              IconButton({
                icon: this.isFavorite ? "❤️" : "🤍",
                onPressed: () => {
                  this.setState(() => {
                    this.isFavorite = !this.isFavorite;
                  });
                }
              })
            ]
          ]
        })
      })
    });
  }
}
```

## Selection Guide

### Choose StatelessWidget when:
- ✅ UI depends only on props
- ✅ No user interaction
- ✅ Doesn't change over time
- ✅ Simple display purpose

### Choose StatefulWidget when:
- ✅ Need to handle user input
- ✅ Have data that changes over time
- ✅ Need animations
- ✅ Need local state management

## Performance Considerations

### StatelessWidget
- No unnecessary rebuilds
- Can use const constructors
- Memory efficient

### StatefulWidget  
- Entire rebuild on setState() call
- State management overhead
- Use only when necessary

## Migration Tips

Start with StatelessWidget and convert to StatefulWidget when state is needed:

```typescript
// Step 1: Start with StatelessWidget
class _MyWidget extends StatelessWidget {
  build(context) {
    return Text("Static text");
  }
}

// Step 2: Convert when state is needed
class _MyWidget extends StatefulWidget {
  createState() => new _MyWidgetState();
}

class _MyWidgetState extends State {
  text = "Dynamic text";
  
  build(context) {
    return GestureDetector({
      onClick: () => {
        this.setState(() => {
          this.text = "Changed!";
        });
      },
      child: Text(this.text)
    });
  }
}
```
