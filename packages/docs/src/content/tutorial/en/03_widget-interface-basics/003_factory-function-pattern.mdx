# Factory Function Pattern (classToFunction)

Did you notice that when using widgets in Flitter, we call `Container()` instead of `new Container()`? This is Flitter's **factory function pattern**. Let's explore why this pattern is important and how it works.

## What You'll Learn

- [ ] The concept and benefits of factory function pattern
- [ ] How classToFunction works
- [ ] Applying factory pattern to custom widgets
- [ ] Writing manual factory functions
- [ ] Practical uses of factory pattern

## Why Use Factory Functions?

### 1. Cleaner Syntax
```typescript
// ❌ Using new keyword (cumbersome)
const widget = new Container({
  child: new Center({
    child: new Text("Hello")
  })
});

// ✅ Factory functions (clean)
const widget = Container({
  child: Center({
    child: Text("Hello")
  })
});
```

### 2. Harmony with Functional Programming
Works well with JavaScript/TypeScript's functional programming style:

```typescript
// Naturally combines with functions that return widgets
const widgets = items.map(item => 
  Container({
    child: Text(item.name)
  })
);
```

### 3. Future Optimization Possibilities
Factory functions can internally apply optimizations like caching and pooling:

```typescript
// Optimizations possible inside factory function
function Container(props) {
  // Caching logic
  if (shouldUseCache(props)) {
    return getCachedWidget(props);
  }
  return new _Container(props);
}
```

> **💡 Core Concept: Factory Pattern**
> 
> The factory pattern is a design pattern that encapsulates object creation.
> 
> In practice, it's used to hide object creation logic, simplify APIs, and provide flexibility.

## Understanding classToFunction

`classToFunction` is a utility that automatically converts widget classes to factory functions:

### Basic Usage
```typescript
// 1. Define class (convention: start with underscore)
class _MyWidget extends StatelessWidget {
  constructor(props) {
    super(props);
    this.color = props.color;
  }
  
  build(context) {
    return Container({
      color: this.color,
      child: Text("My Widget")
    });
  }
}

// 2. Convert with classToFunction
const MyWidget = classToFunction(_MyWidget);

// 3. Use
const widget = MyWidget({ color: Colors.blue });
```

### How It Works Internally
`classToFunction` works roughly like this:

```typescript
function classToFunction(WidgetClass) {
  return function(props) {
    return new WidgetClass(props);
  };
}
```

## Manual Factory Functions

Simple widgets can be created as functions without classes:

```typescript
// Functional widget (Stateless only)
function Badge({ text, color = Colors.red }) {
  return Container({
    padding: EdgeInsets.symmetric({ horizontal: 8, vertical: 4 }),
    decoration: {
      color: color,
      borderRadius: 12
    },
    child: Text(text, {
      style: new TextStyle({
        color: Colors.white,
        fontSize: 12,
        fontWeight: 'bold'
      })
    })
  });
}

// Usage
Badge({ text: "NEW", color: Colors.blue });
```

## Practical Uses of Factory Pattern

### 1. Props Validation
Validate props in factory functions:

```typescript
function Button(props) {
  // Props validation
  if (!props.onPressed && !props.disabled) {
    console.warn("Button: No onPressed and not disabled");
  }
  
  return new _Button(props);
}
```

### 2. Default Value Handling
```typescript
function Card(props) {
  // Apply defaults
  const finalProps = {
    padding: EdgeInsets.all(16),
    elevation: 2,
    ...props
  };
  
  return new _Card(finalProps);
}
```

### 3. Conditional Widget Return
```typescript
function AdaptiveButton(props) {
  // Return different widgets based on platform
  if (isMobile()) {
    return new _MobileButton(props);
  }
  return new _DesktopButton(props);
}
```

## Naming Conventions

Flitter's recommended naming rules:

```typescript
// Internal class: starts with underscore
class _MyWidget extends StatelessWidget { }

// Exported factory function: regular PascalCase
const MyWidget = classToFunction(_MyWidget);

// Filename: kebab-case
// my-widget.ts
```

## Important Notes

### 1. Don't Export Classes Directly
```typescript
// ❌ Don't export classes directly
export class Container extends StatelessWidget { }

// ✅ Always export as factory functions
export const Container = classToFunction(_Container);
```

### 2. Maintain Props Structure
```typescript
// Props are always passed as objects
MyWidget({ color: Colors.blue });  // ✅
MyWidget(Colors.blue);             // ❌
```
