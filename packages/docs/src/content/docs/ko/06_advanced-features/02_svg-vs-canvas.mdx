# Flitter에서 SVG vs Canvas 렌더링

Flitter는 SVG(확장 가능한 벡터 그래픽) 또는 Canvas를 사용하여 그래픽을 렌더링할 수 있는 유연성을 제공합니다. 두 렌더링 방법 모두 각자의 강점이 있으며 다른 시나리오에 적합합니다. 이 두 가지의 차이점을 이해하면 특정 사용 사례에 맞는 올바른 선택을 할 수 있습니다.

## SVG 렌더링

SVG는 XML을 사용하여 2차원 그래픽을 설명하는 벡터 기반 그래픽 형식입니다.

### SVG의 장점:

1. 확장성: SVG 이미지는 품질 손실 없이 모든 크기로 확장할 수 있습니다.
2. 접근성: SVG 요소는 스크린 리더가 읽을 수 있어 더 접근하기 쉽습니다.
3. 상호작용성: SVG 내의 개별 요소는 CSS와 JavaScript로 스타일링하고 조작할 수 있습니다.
4. 작은 파일 크기: 간단한 그래픽의 경우 SVG는 래스터 형식에 비해 파일 크기가 작은 경우가 많습니다.

### SVG의 단점:

1. 성능: 많은 요소가 있는 복잡한 그래픽의 경우 SVG는 렌더링과 조작이 느려질 수 있습니다.
2. 브라우저 지원: 널리 지원되지만 일부 오래된 브라우저는 고급 SVG 기능에 문제가 있을 수 있습니다.

## Canvas 렌더링

Canvas는 JavaScript를 통해 그래픽을 그리는 방법을 제공합니다. 픽셀을 비트맵에 직접 렌더링합니다.

### Canvas의 장점:

1. 성능: Canvas는 일반적으로 많은 요소가 있는 복잡한 그래픽이나 애니메이션을 렌더링하는 데 더 빠릅니다.
2. 픽셀 수준 조작: Canvas는 직접적인 픽셀 조작을 허용하여 이미지 처리에 유용합니다.
3. 3D 지원: WebGL을 통해 Canvas는 3D 그래픽을 지원합니다.

### Canvas의 단점:

1. 비확장성: Canvas 그림은 래스터화되어 확대 시 픽셀화될 수 있습니다.
2. 낮은 접근성: Canvas 콘텐츠는 스크린 리더가 쉽게 읽을 수 없습니다.
3. 내장 상호작용성 없음: 그려진 개별 요소는 이벤트 처리를 위해 접근할 수 없습니다.

## Flitter에서 SVG와 Canvas 선택하기

Flitter는 SVG와 Canvas 렌더링 중에서 선택할 수 있는 유연성을 제공합니다. 렌더링 방법은 AppRunner에 제공하는 요소의 유형 또는 Flitter의 React 및 Svelte 컴포넌트에서 renderer prop에 의해 결정됩니다.

### AppRunner 사용하기

AppRunner를 직접 사용할 때 렌더링 방법은 제공하는 요소의 유형에 의해 결정됩니다:

```typescript
import { AppRunner } from "@meursyphus/flitter";

// SVG 렌더링의 경우
const svgElement = document.createElementNS(
  "http://www.w3.org/2000/svg",
  "svg",
);
const svgRunner = new AppRunner({
  view: svgElement,
});

// Canvas 렌더링의 경우
const canvasElement = document.createElement("canvas");
const canvasRunner = new AppRunner({
  view: canvasElement,
});
```

AppRunner는 SVG 또는 Canvas 요소를 사용하고 있는지 자동으로 감지하고 적절한 렌더링 파이프라인을 설정합니다.

### Flitter-React 또는 Flitter-Svelte 사용하기

Flitter를 React 또는 Svelte와 함께 사용할 때 `renderer` prop을 사용하여 렌더러 유형을 지정할 수 있습니다:

React의 경우:

```jsx
import Widget from '@meursyphus/flitter-react';

// SVG 렌더링
<Widget renderer="svg" widget={yourFlitterWidget} />

// Canvas 렌더링
<Widget renderer="canvas" widget={yourFlitterWidget} />
```

Svelte의 경우:

```svelte
<script>
  import Widget from "@meursyphus/flitter-svelte";
</script>

<!-- SVG 렌더링 -->
<Widget renderer="svg" widget={yourFlitterWidget} />

<!-- Canvas 렌더링 -->
<Widget renderer="canvas" widget={yourFlitterWidget} />
```

이를 통해 Flitter 위젯 코드를 변경하지 않고도 SVG와 Canvas 렌더링 간에 쉽게 전환할 수 있습니다.

## 언제 SVG를 사용해야 하나요?

다음과 같은 경우 SVG를 선택하세요:

1. **간단한 그래픽**: 로고, 아이콘, 간단한 삽화와 같이 복잡도가 낮은 그래픽.
2. **확장성이 필요한 경우**: 품질 손실 없이 다양한 크기로 표시되어야 하는 그래픽.
3. **상호작용성**: 개별 요소에 이벤트 핸들러를 추가해야 하는 경우.
4. **접근성이 중요한 경우**: 시각 장애가 있는 사용자를 고려해야 하는 경우.

## 언제 Canvas를 사용해야 하나요?

다음과 같은 경우 Canvas를 선택하세요:

1. **복잡한 애니메이션**: 많은 요소가 있거나 빠른 업데이트가 필요한 애니메이션.
2. **성능이 중요한 경우**: 특히 많은 수의 요소를 렌더링할 때.
3. **픽셀 조작**: 이미지 처리나 픽셀 수준 효과가 필요한 경우.
4. **게임 개발**: 프레임 속도가 높고 실시간 상호작용이 필요한 경우.

## 성능 고려사항

SVG와 Canvas 중에서 선택할 때 다음 성능 요소를 고려하세요:

1. **요소 수**: 요소가 적은 경우(< 1000개) SVG가 잘 작동합니다. 요소가 많은 경우 Canvas가 더 나은 성능을 제공합니다.
2. **업데이트 빈도**: 자주 업데이트되거나 애니메이션되는 요소의 경우 Canvas가 더 효율적입니다.
3. **메모리 사용량**: SVG는 모든 요소를 DOM에 유지하므로 복잡한 그래픽에서 더 많은 메모리를 사용할 수 있습니다.

## 모범 사례

1. **성능 테스트**: 항상 대상 기기에서 선택한 렌더링 방법을 테스트하세요.
2. **하이브리드 접근**: 필요한 경우 애플리케이션의 다른 부분에 SVG와 Canvas를 함께 사용하는 것을 고려하세요.
3. **최적화**: 어떤 렌더링 방법을 선택하든 코드를 최적화하세요. SVG의 경우 DOM 조작을 최소화하고, Canvas의 경우 그리기 호출을 일괄 처리하세요.

## 결론

Flitter에서 SVG와 Canvas 중 선택은 특정 사용 사례, 성능 요구사항, 접근성 요구에 따라 달라집니다. Flitter의 유연한 아키텍처 덕분에 위젯 코드를 변경하지 않고도 두 렌더링 방법 간에 쉽게 전환할 수 있어 다양한 옵션을 실험하고 프로젝트에 가장 적합한 것을 찾을 수 있습니다.

각 렌더링 방법의 강점과 한계를 이해함으로써 Flitter 애플리케이션에 대해 정보에 입각한 결정을 내릴 수 있고 사용자에게 최상의 경험을 제공할 수 있습니다.
