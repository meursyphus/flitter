## 理解 RenderObject 系统

Flitter 使用与 Flutter 相同的渲染架构。要在屏幕上绘制内容，您需要理解三个树结构。

## Widget 树 → Element 树 → RenderObject 树

  description="Widget 是蓝图，Element 是实例，RenderObject 处理实际渲染"

### 每个树的作用

**Widget 树（蓝图）**
- 声明式表达 UI 结构的不可变对象
- 开发者编写的代码
- 可以每帧重新创建

**Element 树（实例）**
- 连接 Widget 和 RenderObject 的中间层
- 管理状态并处理生命周期
- 即使 Widget 发生变化，Element 也会被重用

**RenderObject 树（渲染）**
- 处理实际的布局计算和绘制
- 包含尺寸、位置和绘制信息
- 性能关键部分，尽可能重用

## 布局和绘制的分离

### performLayout()：尺寸和位置计算

```typescript
class RenderBox {
  performLayout() {
    // 1. 对子节点执行布局
    // 2. 根据子节点的尺寸确定自身尺寸
    // 3. 确定子节点的位置
  }
}
```

### paint()：屏幕上的实际绘制

```typescript
class RenderBox {
  paint(context: PaintingContext, offset: Offset) {
    // 1. 绘制自身内容（背景、边框等）
    // 2. 请求子节点绘制
  }
}
```

### 为什么要分离？

布局和绘制分离是为了**性能优化**：

1. **布局缓存**：如果尺寸或位置没有改变，则不重新计算布局
2. **部分重绘**：当只有颜色改变时，只执行绘制而不进行布局
3. **层优化**：未改变的部分作为层进行缓存

## 探索源代码

Flitter 的 RenderObject 实现可以在 `packages/flitter/src/renderobject/` 目录中找到：

- `RenderObject.ts`：基础 RenderObject 类
- `RenderBox.ts`：实现 2D 盒模型的 RenderBox
- `RenderFlex.ts`：构成 Row 和 Column 基础的 Flex 布局

查看实际实现，您可以看到它与 Flutter 的结构几乎相同。
