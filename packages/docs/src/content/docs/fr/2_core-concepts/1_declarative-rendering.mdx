# Rendu Déclaratif

## Vue d'ensemble

Flitter adopte une approche de rendu **déclarative**, similaire à Flutter. Cela signifie que vous déclarez "comment l'écran devrait apparaître", et Flitter gère automatiquement le rendu. C'est une approche fondamentalement différente de la méthode impérative traditionnelle.

## Pourquoi est-ce important ?

La programmation déclarative offre les avantages suivants :

- **Meilleure lisibilité du code** : Compréhension intuitive de l'apparence de l'interface utilisateur
- **Réduction des bugs** : La gestion simplifiée de l'état conduit à un comportement prévisible
- **Maintenance plus facile** : Mises à jour de l'interface sans manipulation complexe du DOM
- **Productivité accrue** : Implémentation d'interfaces complexes avec moins de code

## Concepts fondamentaux

### Impératif vs Déclaratif

#### Approche Impérative (Exemple D3.js)
Dans l'approche impérative, vous spécifiez quoi faire à chaque étape :

```javascript
// Centrer du texte avec D3.js
const svg = d3.select("svg");
const width = 400;
const height = 200;

// 1. Créer l'élément texte
const text = svg.append("text")
  .text("Bonjour le monde !");

// 2. Mesurer la taille du texte
const bbox = text.node().getBBox();

// 3. Calculer la position centrale
const x = (width - bbox.width) / 2;
const y = (height + bbox.height) / 2;

// 4. Définir la position
text.attr("x", x)
    .attr("y", y);

// Quand l'état change, tous les calculs doivent être refaits
function updateText(newText) {
  text.text(newText);
  const newBbox = text.node().getBBox();
  const newX = (width - newBbox.width) / 2;
  const newY = (height + newBbox.height) / 2;
  text.attr("x", newX).attr("y", newY);
}
```

#### Approche Déclarative (Exemple Flitter)
Dans l'approche déclarative, vous déclarez uniquement le résultat souhaité :

```typescript
// Centrer du texte avec Flitter
Center({
  child: Text("Bonjour le monde !")
})

// Quand l'état change, changez simplement la déclaration
Center({
  child: Text(isFrench ? "Bonjour le monde !" : "Hello, World!")
})
```

### Comment fonctionne le rendu déclaratif

1. **Définir l'état** : Définir l'état actuel de l'application
2. **Déclarer l'interface** : Déclarer comment l'interface doit apparaître en fonction de l'état
3. **Mises à jour automatiques** : Quand l'état change, Flitter met automatiquement à jour l'interface

```typescript
class _CounterWidget extends StatefulWidget {
  createState() {
    return new CounterWidgetState();
  }
}

class CounterWidgetState extends State<_CounterWidget> {
  count = 0;  // Définition de l'état

  build(context: BuildContext): Widget {
    // Déclaration de l'interface - L'interface est déterminée par l'état count
    return Column({
      children: [
        Text(`Compteur actuel : ${this.count}`),
        GestureDetector({
          onClick: () => {
            this.setState(() => {
              this.count++;  // Re-rendu automatique quand l'état change
            });
          },
          child: Container({
            padding: EdgeInsets.all(8),
            color: Colors.blue,
            child: Text("Incrémenter", { style: TextStyle({ color: Colors.white }) })
          })
        })
      ]
    });
  }
}

// Exporter en tant que fonction factory
export default function CounterWidget(): Widget {
  return new _CounterWidget();
}
```

## Exemples pratiques

### 1. Rendu conditionnel

Dans l'approche déclarative, vous pouvez facilement afficher différentes interfaces en utilisant des instructions conditionnelles :

```typescript
class ConditionalExample extends StatefulWidget {
  createState() {
    return new ConditionalExampleState();
  }
}

class ConditionalExampleState extends State<ConditionalExample> {
  isLoggedIn = false;

  build(context: BuildContext): Widget {
    return Center({
      child: this.isLoggedIn 
        ? Column({
            children: [
              Text("Bienvenue !"),
              GestureDetector({
                onClick: () => {
                  this.setState(() => {
                    this.isLoggedIn = false;
                  });
                },
                child: Text("Déconnexion", { 
                  style: TextStyle({ color: Colors.red }) 
                })
              })
            ]
          })
        : GestureDetector({
            onClick: () => {
              this.setState(() => {
                this.isLoggedIn = true;
              });
            },
            child: Container({
              padding: EdgeInsets.all(12),
              color: Colors.blue,
              child: Text("Connexion", { 
                style: TextStyle({ color: Colors.white }) 
              })
            })
          })
    });
  }
}
```

### 2. Rendu de listes

Convertir des données de tableau en interface est également très intuitif :

```typescript
class TodoList extends StatefulWidget {
  createState() {
    return new TodoListState();
  }
}

class TodoListState extends State<TodoList> {
  todos = ["Apprendre Flitter", "Comprendre l'interface déclarative", "Créer une application"];

  build(context: BuildContext): Widget {
    return Column({
      children: [
        Text("Liste de tâches", { 
          style: TextStyle({ fontSize: 20, fontWeight: FontWeight.bold }) 
        }),
        SizedBox({ height: 10 }),
        ...this.todos.map((todo, index) => 
          Container({
            padding: EdgeInsets.all(8),
            margin: EdgeInsets.only({ bottom: 4 }),
            color: Colors.grey.shade200,
            child: Row({
              children: [
                Text(`${index + 1}. ${todo}`),
                Spacer(),
                GestureDetector({
                  onClick: () => {
                    this.setState(() => {
                      this.todos.splice(index, 1);
                    });
                  },
                  child: Icon(Icons.delete, { color: Colors.red })
                })
              ]
            })
          })
        )
      ]
    });
  }
}
```

### 3. Gestion d'état complexe

Même lorsque plusieurs états sont interconnectés, ils peuvent être facilement gérés de manière déclarative :

```typescript
class ShoppingCart extends StatefulWidget {
  createState() {
    return new ShoppingCartState();
  }
}

class ShoppingCartState extends State<ShoppingCart> {
  items = [
    { name: "Pomme", price: 1000, quantity: 0 },
    { name: "Banane", price: 1500, quantity: 0 },
    { name: "Orange", price: 2000, quantity: 0 }
  ];

  get totalPrice() {
    return this.items.reduce((sum, item) => 
      sum + (item.price * item.quantity), 0
    );
  }

  build(context: BuildContext): Widget {
    return Column({
      children: [
        Text("Panier d'achat", { 
          style: TextStyle({ fontSize: 24, fontWeight: FontWeight.bold }) 
        }),
        SizedBox({ height: 20 }),
        ...this.items.map(item => 
          Row({
            children: [
              Text(item.name),
              Spacer(),
              Text(`${item.price} €`),
              SizedBox({ width: 20 }),
              Row({
                children: [
                  GestureDetector({
                    onClick: () => {
                      this.setState(() => {
                        if (item.quantity > 0) item.quantity--;
                      });
                    },
                    child: Icon(Icons.remove_circle)
                  }),
                  Padding({
                    padding: EdgeInsets.symmetric({ horizontal: 10 }),
                    child: Text(`${item.quantity}`)
                  }),
                  GestureDetector({
                    onClick: () => {
                      this.setState(() => {
                        item.quantity++;
                      });
                    },
                    child: Icon(Icons.add_circle)
                  })
                ]
              })
            ]
          })
        ),
        Divider(),
        Text(`Total : ${this.totalPrice} €`, {
          style: TextStyle({ fontSize: 18, fontWeight: FontWeight.bold })
        })
      ]
    });
  }
}
```

## Points importants

1. **Maintenir l'immutabilité** : Ne modifiez pas l'état directement, utilisez toujours `setState`
2. **Fonctions pures** : La méthode `build` doit être une fonction pure sans effets secondaires
3. **Considérations de performance** : Séparez correctement les widgets pour éviter les re-rendus inutiles

```typescript
// ❌ Incorrect - Modification directe de l'état
this.count++;  // L'interface ne se mettra pas à jour

// ✅ Correct - Utiliser setState
this.setState(() => {
  this.count++;
});

// ❌ Incorrect - Effets secondaires dans la méthode build
build(context: BuildContext): Widget {
  // Les effets secondaires comme les appels API doivent être dans initState
  fetch('/api/data');  // Incorrect !
  return Text("...");
}

// ✅ Correct - Gérer les effets secondaires dans initState
initState() {
  super.initState();
  fetch('/api/data').then(data => {
    this.setState(() => {
      this.data = data;
    });
  });
}
```
