## Comprendre le système RenderObject

Flitter utilise la même architecture de rendu que Flutter. Pour afficher quelque chose à l'écran, vous devez comprendre trois structures arborescentes.

## Arbre Widget → Arbre Element → Arbre RenderObject

### Rôle de chaque arbre

**Arbre Widget (Plan)**
- Objets immuables qui expriment de manière déclarative la structure de l'interface
- Code écrit par les développeurs
- Peut être recréé à chaque frame

**Arbre Element (Instance)**
- Couche intermédiaire connectant Widget et RenderObject
- Gère l'état et le cycle de vie
- Les éléments sont réutilisés même quand les Widgets changent

**Arbre RenderObject (Rendu)**
- Gère le calcul de mise en page et le dessin réels
- Contient les informations de taille, position et peinture
- Partie critique pour les performances, réutilisée autant que possible

### performLayout() : Calcul de taille et position

```typescript
class RenderBox {
  performLayout() {
    // 1. Effectuer la mise en page des enfants
    // 2. Déterminer sa propre taille en fonction de la taille des enfants
    // 3. Déterminer la position des enfants
  }
}
```

### paint() : Dessin réel à l'écran

```typescript
class RenderBox {
  paint(context: PaintingContext, offset: Offset) {
    // 1. Dessiner son propre contenu (arrière-plan, bordures, etc.)
    // 2. Demander aux enfants de se dessiner
  }
}
```

### Pourquoi sont-ils séparés ?

Layout et Paint sont séparés pour **l'optimisation des performances** :

1. **Mise en cache du Layout** : Le layout n'est pas recalculé si la taille ou la position ne change pas
2. **Repaint partiel** : Seul le paint est effectué sans layout quand seules les couleurs changent
3. **Optimisation par couches** : Les parties inchangées sont mises en cache comme couches

## Explorer le code source

L'implémentation RenderObject de Flitter se trouve dans le répertoire `packages/flitter/src/renderobject/` :

- `RenderObject.ts` : Classe RenderObject de base
- `RenderBox.ts` : RenderBox implémentant le modèle de boîte 2D
- `RenderFlex.ts` : Mise en page Flex qui forme la base de Row et Column

En regardant l'implémentation réelle, vous pouvez voir qu'elle a une structure presque identique à Flutter.
