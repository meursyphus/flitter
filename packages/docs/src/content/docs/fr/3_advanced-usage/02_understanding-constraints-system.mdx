## Au cœur du système de contraintes

Le système de mise en page de Flitter suit une règle simple :

> **"Les contraintes descendent, les tailles remontent"**

Le parent passe des contraintes à l'enfant, et l'enfant détermine sa taille dans ces contraintes et la rapporte au parent.

## Les contraintes descendent, les tailles remontent

```
        Widget Parent
             │
    ┌────────▼────────┐
    │   Contraintes   │ (descendent)
    │   min: 0x0      │
    │   max: 300x200  │
    └────────┬────────┘
             │
        Widget Enfant
             │
    ┌────────▼────────┐
    │  Décide la taille│ (remonte)
    │   choisie: 150x80│
    └─────────────────┘
```

### Composants de BoxConstraints

```typescript
class BoxConstraints {
  minWidth: number;   // Largeur minimale
  maxWidth: number;   // Largeur maximale  
  minHeight: number;  // Hauteur minimale
  maxHeight: number;  // Hauteur maximale
}
```

L'enfant peut choisir sa taille dans ces contraintes :
- `minWidth ≤ width ≤ maxWidth`
- `minHeight ≤ height ≤ maxHeight`

## Principaux modèles de contraintes

### 1. Contraintes strictes (Tight)
```typescript
Constraints.tight(new Size(100, 50))
// minWidth = maxWidth = 100
// minHeight = maxHeight = 50
```
```
┌─────────────┐
│ Exactement 100x50 │  ← L'enfant est forcé à cette taille
└─────────────┘
```

### 2. Contraintes souples (Loose)
```typescript
Constraints.loose(new Size(100, 50))
// minWidth = minHeight = 0
// maxWidth = 100, maxHeight = 50
```
```
┌─────────────┐
│ 0x0 ~ 100x50│  ← L'enfant choisit librement dans cette plage
└─────────────┘
```

### 3. Contraintes expansées
```typescript
Constraints.expand()
// minWidth = maxWidth = ∞
// minHeight = maxHeight = ∞
```
```
┌─────────────┐
│ Taille maximale│  ← Occupe tout l'espace parent
└─────────────┘
```

### 4. Sans contraintes
```typescript
UnconstrainedBox({
  child: Container({ width: 1000 })  // Ignore les contraintes parent
})
```
```
Parent: max 300px
    │
    ▼
UnconstrainedBox  ──→  Enfant: 1000px (débordement possible)
```

## Comprendre le comportement réel

### Container vs SizedBox

```typescript
// La largeur/hauteur du Container sont des "souhaits"
Container({
  width: 200,   // ← Si le parent n'autorise que 100px, devient 100px
  height: 100,
  child: Text("Bonjour")
})

// SizedBox "force" sa taille
SizedBox({
  width: 200,   // ← Force exactement 200px à l'enfant
  height: 100,
  child: Text("Bonjour")
})
```

### Contraintes dans Column

```
Column (hauteur: ∞)
  │
  ├─ Enfant 1 (hauteur: taille naturelle stricte)
  ├─ Enfant 2 (hauteur: taille naturelle stricte)  
  └─ Enfant 3 (hauteur: taille naturelle stricte)
```

Column ne contraint pas "strictement" la hauteur de ses enfants. Chaque enfant peut prendre la hauteur qu'il souhaite.

## Problèmes courants et solutions

### Problème 1 : Erreur de taille infinie
```typescript
// ❌ Column dans Column reçoit une hauteur infinie
Column({
  children: [
    Column({ children: [...] })  // RenderFlex overflowed!
  ]
})

// ✅ Utiliser Expanded pour limiter la taille
Column({
  children: [
    Expanded({
      child: Column({ children: [...] })
    })
  ]
})
```

### Problème 2 : Le widget n'obtient pas la taille désirée
```typescript
// ❌ Le parent passe des contraintes strictes
Container({
  width: 100,
  height: 100,
  child: Container({
    width: 200,  // Ignoré ! (forcé à 100px)
    height: 200
  })
})

// ✅ Libérer les contraintes avec UnconstrainedBox
Container({
  width: 100,
  height: 100,
  child: UnconstrainedBox({
    child: Container({
      width: 200,  // Appliqué (un débordement peut survenir)
      height: 200
    })
  })
})
```

### Problème 3 : L'alignement au centre ne fonctionne pas
```typescript
// ❌ Container s'ajuste à la taille parent
Row({
  children: [
    Container({
      color: 'red',
      child: Text('Bonjour')  // Container ne prend que la taille du texte
    })
  ]
})

// ✅ Taille explicite ou utiliser Expanded
Row({
  children: [
    Expanded({
      child: Container({
        color: 'red',
        alignment: Alignment.center,
        child: Text('Bonjour')
      })
    })
  ]
})
```

## Points clés à retenir

1. **Le parent passe les contraintes** → l'enfant décide de sa taille → rapporte au parent
2. **Contraintes = plage de taille** (largeur/hauteur min/max)
3. **tight** : force une taille exacte, **loose** : limite seulement la taille maximale
4. **Comprendre cela rend les problèmes de mise en page faciles à résoudre**
