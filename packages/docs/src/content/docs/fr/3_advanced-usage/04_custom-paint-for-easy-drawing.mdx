## Contexte du widget CustomPaint

Le RenderObjectWidget que nous avons appris précédemment est puissant mais complexe. Même quand vous voulez simplement dessiner quelque chose, vous devez hériter de RenderObject, implémenter createRenderObject et surcharger la méthode paint.

CustomPaint résout cette complexité. Il suffit de passer le comportement de peinture comme fonction de première classe et c'est terminé !

### Avantages de CustomPaint

1. **API simple** : Il suffit de passer la fonction painter
2. **Prototypage rapide** : Pas besoin de structure de classe complexe
3. **Réutilisabilité** : Facile de remplacer les fonctions painter
4. **Performance** : Utilise un RenderObject optimisé en interne

### Utilisation de base

```typescript
// Pour le renderer SVG
CustomPaint({
  size: new Size(300, 200),
  painter: {
    svg: {
      createDefaultSvgEl(context) {
        return {
          circle: context.createSvgEl('circle')
        };
      },
      paint(els, size) {
        els.circle.setAttribute('cx', `${size.width / 2}`);
        els.circle.setAttribute('cy', `${size.height / 2}`);
        els.circle.setAttribute('r', '50');
        els.circle.setAttribute('fill', '#3B82F6');
      }
    }
  }
})

// Pour le renderer Canvas
CustomPaint({
  size: new Size(300, 200),
  painter: {
    canvas: {
      paint(context, size) {
        const ctx = context.canvas;
        ctx.fillStyle = '#3B82F6';
        ctx.beginPath();
        ctx.arc(size.width / 2, size.height / 2, 50, 0, Math.PI * 2);
        ctx.fill();
      }
    }
  }
})
```

### Optimisation shouldRepaint

Vous pouvez contrôler quand repeindre pour les performances :

```typescript
CustomPaint({
  painter: {
    dependencies: myData, // Données de dépendance
    shouldRepaint: (oldPainter) => {
      // Retourner true pour repeindre
      // Retourner false pour garder la peinture précédente
      return oldPainter.dependencies !== myData;
    },
    svg: {
      // Implémentation SVG
    },
    canvas: {
      // Implémentation Canvas
    }
  }
})
```

## Rendu SVG vs Canvas

CustomPaint de Flitter supporte deux méthodes de rendu :

### Rendu SVG
- **Maintient la qualité lors du redimensionnement**
- **Convient aux graphiques vectoriels**
- **Créer des éléments SVG avec createDefaultSvgEl()**
- **Définir les attributs avec setAttribute dans paint()**

```typescript
svg: {
  createDefaultSvgEl(context) {
    return {
      line: context.createSvgEl('path'),
      point: context.createSvgEl('circle')
    };
  },
  paint(els, size) {
    els.line.setAttribute('d', pathData);
    els.line.setAttribute('stroke', '#3B82F6');
    els.point.setAttribute('cx', '50');
    els.point.setAttribute('cy', '50');
  }
}
```

### Rendu Canvas
- **Convient à la manipulation complexe de pixels**
- **Avantageux pour les animations haute performance**
- **Même approche que l'API Canvas web**

```typescript
canvas: {
  paint(context, size) {
    const ctx = context.canvas;
    ctx.fillStyle = '#3B82F6';
    ctx.fillRect(0, 0, size.width, size.height);
    ctx.strokeStyle = '#FF0000';
    ctx.lineWidth = 2;
    ctx.beginPath();
    ctx.moveTo(0, 0);
    ctx.lineTo(100, 100);
    ctx.stroke();
  }
}
```

## Résumé des points clés

1. **CustomPaint cache la complexité de RenderObject**
2. **Fournit des implémentations svg/canvas séparées dans l'objet painter**
3. **Les performances peuvent être optimisées avec dependencies et shouldRepaint**
4. **Supporte les méthodes de rendu SVG et Canvas**
5. **Vous n'avez besoin de fournir l'implémentation que pour le renderer que vous utilisez**
6. **Peut être facilement combiné avec des animations**
