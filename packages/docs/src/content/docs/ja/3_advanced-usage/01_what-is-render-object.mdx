## RenderObjectシステムの理解

FlitterはFlutterと同じレンダリングアーキテクチャを使用しています。画面に何かを描画するには、3つのツリー構造を理解する必要があります。

### 各ツリーの役割

**Widget Tree（設計図）**
- UI構造を宣言的に表現する不変オブジェクト
- 開発者が書くコード
- 毎フレーム再作成されることが可能

**Element Tree（インスタンス）**
- WidgetとRenderObjectをつなぐ中間層
- 状態を管理し、ライフサイクルを処理
- Widgetが変更されてもElementは再利用される

**RenderObject Tree（レンダリング）**
- 実際のレイアウト計算と描画を担当
- サイズ、位置、ペイント情報を保持
- パフォーマンス上重要な部分で、可能な限り再利用

### performLayout(): サイズと位置の計算

```typescript
class RenderBox {
  performLayout() {
    // 1. 子要素のレイアウトを実行
    // 2. 子要素のサイズに基づいて自身のサイズを決定
    // 3. 子要素の位置を決定
  }
}
```

### paint(): 画面への実際の描画

```typescript
class RenderBox {
  paint(context: PaintingContext, offset: Offset) {
    // 1. 自身のコンテンツを描画（背景、ボーダーなど）
    // 2. 子要素にペイントをリクエスト
  }
}
```

### なぜ分離されているのか？

レイアウトとペイントは**パフォーマンス最適化**のために分離されています：

1. **レイアウトキャッシュ**: サイズや位置が変わらなければレイアウトは再計算されない
2. **部分的な再描画**: 色のみが変更された場合、レイアウトなしでペイントのみ実行
3. **レイヤー最適化**: 変更されない部分はレイヤーとしてキャッシュ

## ソースコードを探る

FlitterのRenderObject実装は`packages/flitter/src/renderobject/`ディレクトリにあります：

- `RenderObject.ts`: ベースとなるRenderObjectクラス
- `RenderBox.ts`: 2Dボックスモデルを実装するRenderBox
- `RenderFlex.ts`: RowやColumnの基礎となるFlexレイアウト

実際の実装を見ると、Flutterとほぼ同じ構造であることがわかります。
