## Constraintsシステムのコア

Flitterのレイアウトシステムは1つのシンプルなルールに従います：

> **「制約は下へ、サイズは上へ」**

親が子に制約を渡し、子はその制約内で自身のサイズを決定して親に報告します。

## Constraints go down, Sizes go up

```
        Parent Widget
             │
    ┌────────▼────────┐
    │   Constraints   │ (go down)
    │   min: 0x0      │
    │   max: 300x200  │
    └────────┬────────┘
             │
        Child Widget
             │
    ┌────────▼────────┐
    │   Decides Size  │ (goes up)
    │   chosen: 150x80│
    └─────────────────┘
```

### BoxConstraintsの構成要素

```typescript
class BoxConstraints {
  minWidth: number;   // 最小幅
  maxWidth: number;   // 最大幅  
  minHeight: number;  // 最小高さ
  maxHeight: number;  // 最大高さ
}
```

子要素はこの制約内で自分のサイズを選択できます：
- `minWidth ≤ width ≤ maxWidth`
- `minHeight ≤ height ≤ maxHeight`

## 主要なConstraintsパターン

### 1. Tight Constraints
```typescript
Constraints.tight(new Size(100, 50))
// minWidth = maxWidth = 100
// minHeight = maxHeight = 50
```
```
┌─────────────┐
│ 正確に 100x50 │  ← 子要素はこのサイズに強制される
└─────────────┘
```

### 2. Loose Constraints  
```typescript
Constraints.loose(new Size(100, 50))
// minWidth = minHeight = 0
// maxWidth = 100, maxHeight = 50
```
```
┌─────────────┐
│ 0x0 ~ 100x50│  ← 子要素が範囲内で自由に選択
└─────────────┘
```

### 3. Expand Constraints
```typescript
Constraints.expand()
// minWidth = maxWidth = ∞
// minHeight = maxHeight = ∞
```
```
┌─────────────┐
│ 可能な最大サイズ│  ← 親の空間をすべて占有
└─────────────┘
```

### 4. Unconstrained
```typescript
UnconstrainedBox({
  child: Container({ width: 1000 })  // 親の制約を無視
})
```
```
Parent: 最大 300px
    │
    ▼
UnconstrainedBox  ──→  Child: 1000px (オーバーフローの可能性)
```

## 実際の動作を理解する

### Container vs SizedBox

```typescript
// Containerのwidth/heightは「希望」
Container({
  width: 200,   // ← 親が100pxしか許可しなければ100pxになる
  height: 100,
  child: Text("Hello")
})

// SizedBoxはサイズを「強制」
SizedBox({
  width: 200,   // ← 子要素に正確に200pxを強制
  height: 100,
  child: Text("Hello")
})
```

### Column内でのConstraints

```
Column (高さ: ∞)
  │
  ├─ Child 1 (高さ: tight natural size)
  ├─ Child 2 (高さ: tight natural size)  
  └─ Child 3 (高さ: tight natural size)
```

Columnは子要素の高さを「tightly」制約しません。各子要素は必要なだけの高さを取ることができます。

## よくある問題と解決策

### 問題1: 無限サイズエラー
```typescript
// ❌ Column内のColumnは無限の高さを受け取る
Column({
  children: [
    Column({ children: [...] })  // RenderFlexがオーバーフロー！
  ]
})

// ✅ Expandedでサイズを制限
Column({
  children: [
    Expanded({
      child: Column({ children: [...] })
    })
  ]
})
```

### 問題2: ウィジェットが希望サイズにならない
```typescript
// ❌ 親がtightな制約を渡す
Container({
  width: 100,
  height: 100,
  child: Container({
    width: 200,  // 無視される！（100pxに強制）
    height: 200
  })
})

// ✅ UnconstrainedBoxで制約を解除
Container({
  width: 100,
  height: 100,
  child: UnconstrainedBox({
    child: Container({
      width: 200,  // 適用される（オーバーフローの可能性）
      height: 200
    })
  })
})
```

### 問題3: 中央揃えが効かない
```typescript
// ❌ Containerは親のサイズにフィットする
Row({
  children: [
    Container({
      color: 'red',
      child: Text('Hello')  // Containerはテキストサイズのみ取る
    })
  ]
})

// ✅ 明示的なサイズまたはExpandedを使用
Row({
  children: [
    Expanded({
      child: Container({
        color: 'red',
        alignment: Alignment.center,
        child: Text('Hello')
      })
    })
  ]
})
```

- `packages/flitter/src/type/constraints.ts`: BoxConstraintsクラス
- `packages/flitter/src/renderobject/RenderBox.ts`: Constraintの処理ロジック

## 主要なポイント

1. **親が制約を渡す** → 子がサイズを決定 → 親に報告
2. **Constraints = サイズ範囲** (min/max width/height)
3. **tight**: 正確なサイズを強制、**loose**: 最大サイズのみ制限
4. **これを理解すればレイアウトの問題が簡単に解決できる**
