# Interaction

The editor wires every gesture itself, so custom nodes and edges never need their own drag or click handlers. This page lists the gestures by input, then covers the features you configure: viewport limits, reconnecting edges, resizing nodes and node toolbars.

The examples use the same public imports as a CLI install. The [gallery](/diagram/gallery) shows how these engine interactions work with custom compositions.

## Mouse and trackpad

| Gesture | Result | Option |
| --- | --- | --- |
| Drag the background | Pan | `panOnDrag` |
| Mouse wheel | Zoom toward the pointer, or pan with `panOnScroll` | `zoomOnScroll`, `panOnScroll` |
| Trackpad pinch | Zoom toward the pointer. Browsers report it as a wheel event with Ctrl held. | `zoomOnPinch` |
| Double-click the background | Zoom in 2×; Shift+double-click zooms out | `zoomOnDoubleClick` |
| Click a node or edge | Select it. Clicking the background clears the selection. | `elementsSelectable` |
| Cmd+click (macOS) or Ctrl+click | Add to or remove from the selection | `multiSelectionKeyCode` |
| Shift+drag the background | Box-select nodes, plus the edges between them | `selectionKeyCode`, `selectionOnDrag` |
| Drag a node | Move it. Dragging a selected node moves the whole selection. | `nodesDraggable` |
| Drag from a handle to another handle | Connect them | `nodesConnectable` |
| Click a handle, then another | Connect them | `connectOnClick` |
| Drag the end of an edge | Reconnect it, see Reconnecting edges | `edgesReconnectable` |
| Drag a resize control | Resize the node, see Resizing nodes | `nodesResizable` |
| Drag the minimap | Pan | `config.minimap.pannable` |

Dragging a node or a connection near the pane edge pans the view (`autoPanOnNodeDrag`, `autoPanOnConnect`).

## Keyboard

| Key | Result | Option |
| --- | --- | --- |
| Backspace or Delete | Delete the selection and every edge attached to it | `deleteKeyCode` |
| Shift, held | Dragging the background box-selects | `selectionKeyCode` |
| Cmd or Ctrl, held | Clicking adds to the selection. With `panOnScroll`, the wheel zooms. | `multiSelectionKeyCode`, `zoomActivationKeyCode` |
| Space, held | Dragging the background pans, even when it would box-select | `panActivationKeyCode` |
| Escape | Cancel a connection or reconnection in progress | |

The editor listens on the whole document and ignores keys typed into inputs, textareas, selects and editable elements. See the [Keyboard options](/diagram/api) for the key names.

## Touch

Flitter turns touch input into the mouse events the editor already handles, so touch needs no options of its own. The core does this for every Flitter widget with drag handlers, so [`InteractiveViewer`](/advanced/widgets/interactive-viewer) responds to touch the same way.

| Gesture | Result |
| --- | --- |
| Tap | A click. Selects a node or edge, clears the selection on the background, and completes a click connection. |
| One finger on a node | Drags it |
| One finger on the background | Pans |
| One finger from a handle | Draws a connection |
| One finger on an edge end or a resize control | Reconnects the edge or resizes the node |
| Two fingers | Pinch to zoom around their midpoint; move both to pan |

How it behaves:

- **The pinch midpoint is the pointer.** Lifting one finger hands over to the other without a jump.
- **Pinching uses `zoomOnPinch`.** Set it to `false` to turn pinch zoom off. `minZoom` and `maxZoom` still apply.
- **There is no hover.** Hover styles end when the finger lifts.
- **There are no modifier keys.** Shift+drag box selection and Cmd/Ctrl+click need a hardware keyboard.
- **The diagram captures touches that start on it.** The page does not scroll from there, while touches elsewhere scroll it as usual. On phones, leave some page around a full-width diagram so readers can still scroll past it.

Callbacks receive the synthesized `MouseEvent`. It carries `fromTouch: true`, which `SyntheticPointerEvent` from `flitter-ui` types:

```typescript
import type { SyntheticPointerEvent } from "flitter-ui";

FlowDiagram({
  nodes,
  edges,
  onNodeClick: (event, node) => {
    const input = (event as SyntheticPointerEvent).fromTouch ? "touch" : "mouse";
    console.log(`${node.id} clicked with ${input}`);
  },
});
```

## Viewport limits

`minZoom` and `maxZoom` bound the zoom. `translateExtent` bounds the area the viewport may show, as `[[minX, minY], [maxX, maxY]]` in flow coordinates.

```typescript
FlowDiagram({
  nodes,
  edges,
  minZoom: 1,
  translateExtent: [
    [0, 0],
    [1200, 800],
  ],
});
```

The extent is enforced on every viewport change: dragging, the wheel, pinching, auto-pan, the minimap, controller calls such as `setViewport`, `fitView` and `setCenter`, and the initial `defaultViewport` once the pane has a size. When the extent is narrower or shorter than the pane at the current zoom, it is centred on that axis instead. The extent does not limit zoom, so pair it with a `minZoom` that keeps it larger than the pane if users must never see past it.

## Reconnecting edges

Drag either end of an edge onto another handle to move that end. The line snaps to handles within `connectionRadius` and checks the target with `connectionMode` and `isValidConnection`, exactly like a new connection. Dropping it anywhere else leaves the edge unchanged.

The grab area is a circle of `reconnectRadius`, 10 flow units by default, centred on each end of the edge. Node handles are drawn above it and take the press where they overlap, so press on the edge just outside the handle. Pressing the handle itself starts a new connection instead.

| Option | Default | Description |
| --- | --- | --- |
| `edgesReconnectable` | `true` | Allow reconnecting edges. Set it to `false` to turn reconnecting off while keeping new connections. |
| `reconnectRadius` | `10` | Radius of each end's grab area in flow units |
| `edge.reconnectable` | Both ends | `true`, `"source"`, `"target"` or `false`, per edge |

Reconnecting also stops when `nodesConnectable` is `false` and while interaction is locked from the controls.

### Applying the change

Without `onReconnect`, the editor calls `controller.reconnectEdge(oldEdge, connection)`. That emits a `replace` change keyed by the old id, and the edge gets the id `getEdgeId(connection)` generates, `xy-edge__…`, as React Flow's `reconnectEdge` does. With `onReconnect`, the editor changes nothing and you decide:

```typescript
FlowDiagram({
  controller,
  nodes,
  edges,
  isValidConnection: (connection) => connection.source !== connection.target,
  onReconnect: (oldEdge, connection) => {
    // Keep the edge's id instead of generating a new one
    controller.reconnectEdge(oldEdge, connection, { shouldReplaceId: false });
  },
  onReconnectEnd: (_event, edge, end, state) => {
    if (state.isValid === null) console.log(`The ${end} end of ${edge.id} was dropped away from a handle`);
  },
});
```

| Callback | Arguments |
| --- | --- |
| `onReconnectStart` | `(event, edge, handleType)`, where `handleType` is the end being moved |
| `onReconnect` | `(oldEdge, connection)` when the end lands on a valid handle |
| `onReconnectEnd` | `(event, edge, handleType, state)` when the drag ends, valid or not |

`onConnect`, `onConnectStart` and `onConnectEnd` do not fire for reconnections.

### While dragging

`controller.connection` describes the gesture like a new connection does. `reconnectingEdge` is the edge and `reconnectingEnd` the end being moved. `fromNode` and `fromHandle` are the end that stays attached, which is where the connection line starts.

Edge builders receive `reconnecting: true` for that edge. The built-in edge draws it in `colors.edgeStrokeUpdating`, a grey.

`custom.reconnectHandle` draws the grab areas. It receives `{ edge, end, size }`, where `size` is the diameter, and the widget it returns is centred on the end. The built-in one is an invisible box. This one shows a dot on the ends of selected edges:

```typescript
import { Alignment, BoxDecoration, Container } from "flitter-ui";

FlowDiagram({
  nodes,
  edges,
  custom: {
    reconnectHandle: ({ edge, size }) =>
      Container({
        width: size,
        height: size,
        alignment: Alignment.center,
        child: edge.selected
          ? Container({ width: 8, height: 8, decoration: new BoxDecoration({ shape: "circle", color: "#3367d9" }) })
          : undefined,
      }),
  },
});
```

## Resizing nodes

Resize controls appear around a node while it is selected, if it is resizable. Turn them on for every node with `nodesResizable: true`, or per node with `resizable`. A node's `resizable` wins in both directions. Locking interaction from the controls hides them.

By default a node gets a line along each side and a handle on each corner. Lines change one dimension and corners change both. Resizing from a top or left control moves the node so the opposite side stays in place.

```typescript
FlowDiagram({
  nodes: [
    { id: "note", position: { x: 0, y: 0 }, data: { label: "Resize me" }, resizable: true },
    {
      id: "frame",
      position: { x: 220, y: 0 },
      width: 160,
      height: 90,
      data: { label: "16:9" },
      resizable: true,
      resizeOptions: { keepAspectRatio: true, minWidth: 80, handles: ["bottom-right"], lines: [] },
    },
  ],
  edges: [],
  nodeResizeOptions: { minWidth: 100, minHeight: 40, maxWidth: 400 },
  onNodeResizeEnd: (_event, node, { width, height }) => console.log(node.id, width, height),
});
```

| `NodeResizeOptions` | Default | Description |
| --- | --- | --- |
| `minWidth`, `minHeight` | `10` | Smallest size in flow units |
| `maxWidth`, `maxHeight` | None | Largest size |
| `keepAspectRatio` | `false` | Keep the ratio the node had when the resize started |
| `handles` | The four corners | Handles to show: `"top-left"`, `"top-right"`, `"bottom-left"`, `"bottom-right"`, and the sides `"top"`, `"right"`, `"bottom"`, `"left"` |
| `lines` | All four sides | Side lines to show. `[]` hides them. |

The `nodeResizeOptions` prop sets the defaults and each node's `resizeOptions` is merged over them. With `snapToGrid`, the width and height snap to `snapGrid` without going below the minimum.

### What a resize changes

The new size is written to `node.width` and `node.height`, so the node keeps it. From then on its widget is laid out at exactly that size, so a custom node should let its content grow and shrink. While resizing, `node.resizing` is `true` and node builders receive `resizing: true`.

`onNodesChange` receives `dimensions` changes with `resizing: true` and `setAttributes: true`, a `position` change when a top or left control moves the node, and a final `dimensions` change with `resizing: false`.

| Callback | Arguments |
| --- | --- |
| `onNodeResizeStart` | `(event, node)` |
| `onNodeResize` | `(event, node, params)` on every pointer move |
| `onNodeResizeEnd` | `(event, node, params)` with the last params |

`params` is `{ x, y, width, height, direction }`. `x` and `y` are the node's position, relative to its parent when it has one. `direction` holds the sign of the pointer movement on each axis.

Resizing respects `nodeExtent` and the node's `extent`. The resized box stays inside the extent, and a child with `extent: "parent"` stays inside its parent. The extent is applied after `keepAspectRatio`, so a box clamped by it can lose its ratio, and the minimum size still wins when the extent is smaller than it.

`custom.resizeControl` draws each line and handle. It receives `{ node, position, variant, resizing }`, where `variant` is `"line"` or `"handle"`. The widget's size is its grab area. The `resize` tokens of [Styling](/diagram/api/styling) change the built-in look.

## Node toolbar

A toolbar is a widget shown beside a node, like React Flow's `NodeToolbar`. Give every node type the same toolbar with the `nodeToolbar` prop, or one node type its own with `toolbar` in `nodeTypes`. A type's `toolbar` takes precedence over the prop.

```typescript
import {
  Container, EdgeInsets, GestureDetector, MainAxisSize, Row, SizedBox, Text, TextStyle, type Widget,
} from "flitter-ui";
import { FlowDiagram } from "@/components/diagram/flow-diagram";

function button(label: string, onClick: () => void): Widget {
  return GestureDetector({
    onClick,
    child: Container({
      padding: EdgeInsets.symmetric({ horizontal: 8, vertical: 4 }),
      color: "#1a192b",
      child: Text(label, { style: new TextStyle({ color: "#ffffff", fontSize: 12 }) }),
    }),
  });
}

FlowDiagram({
  nodes,
  edges,
  nodeToolbar: ({ node }, flow) =>
    Row({
      mainAxisSize: MainAxisSize.min,
      children: [
        button("Duplicate", () =>
          flow.addNodes({
            id: crypto.randomUUID(),
            type: node.type,
            data: node.data,
            position: { x: node.position.x + 40, y: node.position.y + 40 },
          }),
        ),
        SizedBox({ width: 4 }),
        button("Delete", () => void flow.deleteElements({ nodes: [node] })),
      ],
    }),
});
```

The builder receives `{ node, selected }` and the context, which is the controller with `config` attached. Return `null` to show nothing for a node.

By default the toolbar shows while its node is the only selected node. `node.toolbar` places it and can force it:

| `node.toolbar` | Default | Description |
| --- | --- | --- |
| `position` | `"top"` | Side of the node: `"top"`, `"right"`, `"bottom"` or `"left"` |
| `align` | `"center"` | `"start"`, `"center"` or `"end"` along that side |
| `offset` | `10` | Gap between the node and the toolbar in screen pixels |
| `isVisible` | Unset | `true` always shows the toolbar, `false` never does |

```typescript
import { Text } from "flitter-ui";
import { FlowDiagram, xyflowNode } from "@/components/diagram/flow-diagram";

FlowDiagram({
  nodes: [
    { id: "a", type: "task", position: { x: 0, y: 0 }, data: { label: "Task" }, toolbar: { position: "right", align: "start" } },
    { id: "b", type: "task", position: { x: 0, y: 120 }, data: { label: "Pinned" }, toolbar: { isVisible: true, position: "bottom" } },
  ],
  edges: [],
  nodeTypes: {
    task: { build: xyflowNode, toolbar: ({ node }) => Text(`Task ${node.id}`) },
  },
});
```

The toolbar lives in screen space. It keeps its size at every zoom level and follows the node while you pan, zoom or drag. It is drawn above the nodes and below the panels. Clicks inside it do not reach the pane, so pressing a button neither clears the selection nor starts a pan.

Toolbars are rebuilt with the pane, on every change of the diagram, including each frame of a pan. Keep them light.

## Locking interaction

The lock button in the controls calls `controller.setInteractive(false)`. Panning and zooming keep working. Nodes can no longer be selected, connected or resized, and edges can no longer be reconnected. Nodes can no longer be dragged either, except those with `draggable: true`, which stays in force under the lock. A node that was selected before the lock keeps its toolbar.

Use the options to turn single gestures off for good, for example a read-only viewer:

```typescript
FlowDiagram({
  nodes,
  edges,
  nodesDraggable: false,
  nodesConnectable: false,
  elementsSelectable: false,
  zoomOnDoubleClick: false,
  config: { controls: { showInteractive: false } },
});
```

`nodesConnectable: false` also turns off reconnecting edges.

## Viewport options

| Option | Default | Description |
| --- | --- | --- |
| `minZoom` | `0.5` | Smallest zoom for gestures and controller calls |
| `maxZoom` | `2` | Largest zoom |
| `zoomOnScroll` | `true` | Mouse wheel zooms toward the pointer, using d3-zoom's curve |
| `zoomOnPinch` | `true` | Trackpad pinch (a wheel event with Ctrl or Meta held) zooms |
| `panOnScroll` | `false` | Wheel pans instead of zooming; pinch still zooms |
| `panOnScrollSpeed` | `0.5` | Multiplier for wheel panning |
| `zoomOnDoubleClick` | `true` | Double-click the background to zoom in 2×, Shift+double-click to zoom out |
| `panOnDrag` | `true` | Dragging the background pans |
| `autoPanOnNodeDrag` | `true` | Pan when a dragged node nears the pane edge |
| `autoPanOnConnect` | `true` | Pan when a connection line nears the pane edge |
| `autoPanSpeed` | `15` | Pixels per frame for auto-pan |
| `translateExtent` | Unbounded | `[[minX, minY], [maxX, maxY]]` in flow coordinates. The viewport never shows anything outside it. |

`translateExtent` clamps every viewport change: dragging, the wheel, pinching, auto-pan, the minimap, controller calls such as `setViewport`, `fitView` and `setCenter`, and the initial `defaultViewport` once the pane has a size. When the extent is narrower or shorter than the pane at the current zoom, it is centred on that axis. It does not limit zoom; combine it with `minZoom` to stop users zooming out past it.

## Selection and dragging

| Option | Default | Description |
| --- | --- | --- |
| `elementsSelectable` | `true` | Nodes and edges can be selected. `selectable: false` turns it off for one node or edge. |
| `selectionOnDrag` | `false` | Dragging the background box-selects instead of panning |
| `selectionMode` | `"full"` | `"full"` selects nodes fully inside the box, `"partial"` any overlap |
| `nodesDraggable` | `true` | Nodes can be dragged; a node's `draggable` overrides it |
| `selectNodesOnDrag` | `true` | Dragging an unselected node selects it first |
| `nodeDragThreshold` | `1` | Pixels the pointer must move before a drag starts |
| `snapToGrid` | `false` | Snap dragged positions to `snapGrid` |
| `snapGrid` | `[15, 15]` | Grid size for snapping |
| `nodeExtent` | Unbounded | `[[minX, minY], [maxX, maxY]]` that nodes stay inside while dragged or resized |
| `elevateNodesOnSelect` | `true` | Draw selected nodes above the rest |
| `elevateEdgesOnSelect` | `false` | Draw selected edges above the rest |

## Connections

| Option | Default | Description |
| --- | --- | --- |
| `nodesConnectable` | `true` | Handles start connections. `connectable: false` on a node or handle turns it off for that one. |
| `connectionMode` | `"strict"` | `"strict"` connects source to target only; `"loose"` lets any handle connect to any other |
| `connectionRadius` | `20` | Distance in flow units within which the line snaps to a handle, also when reconnecting an edge |
| `connectOnClick` | `true` | Click one handle, then another, to connect |
| `isValidConnection` | `() => true` | Reject a candidate connection by returning `false`. Reconnections are checked too. |
| `connectionLineType` | `"default"` | Path type of the line drawn while connecting |
| `defaultEdgeOptions` | `{}` | Fields merged into edges added by connecting or `controller.addEdges()`. Not applied to the `edges` prop. |

## Reconnecting and resizing

| Option | Default | Description |
| --- | --- | --- |
| `edgesReconnectable` | `true` | Dragging either end of an edge onto another handle reconnects it. `edge.reconnectable` limits it per edge. Also needs `nodesConnectable`. |
| `reconnectRadius` | `10` | Radius in flow units of the grab area at each edge end, so it is 20 units across |
| `nodesResizable` | `false` | Selected nodes show resize controls. `node.resizable` overrides it per node. |
| `nodeResizeOptions` | `{ minWidth: 10, minHeight: 10 }` | Default `NodeResizeOptions`, merged under each node's `resizeOptions` |

React Flow has no props for resizing or toolbars. It uses the `NodeResizer` and `NodeToolbar` components, which `nodesResizable`, `nodeResizeOptions` and the `nodeToolbar` prop replace here.

Reconnecting also stops when `nodesConnectable` is `false`. Reconnecting and resizing both stop while interaction is locked, with the controls' lock button or `controller.setInteractive(false)`. See [Interaction](/diagram/api/interaction) for the gestures and the resize options.

## Keyboard

Each option takes a key name, an array of names, or `null` to disable it. Names are `KeyboardEvent.key` values, with `"Space"` for the space bar. Keys typed into an input, textarea, select or editable element are ignored.

| Option | Default | Description |
| --- | --- | --- |
| `deleteKeyCode` | `["Backspace", "Delete"]` | Deletes selected nodes and edges, and edges attached to deleted nodes |
| `selectionKeyCode` | `"Shift"` | Hold to box-select by dragging |
| `multiSelectionKeyCode` | `"Meta"` on macOS, else `"Control"` | Hold while clicking to add to or remove from the selection |
| `panActivationKeyCode` | `"Space"` | Hold to pan by dragging, even when dragging would box-select |
| `zoomActivationKeyCode` | `"Meta"` on macOS, else `"Control"` | Hold to make the wheel zoom while `panOnScroll` is on |

Escape cancels a connection in progress.

The editor listens for keys on the whole document. The pan key only calls `preventDefault` while the pointer is over the diagram, so Space still scrolls the page and presses focused buttons everywhere else.

## Hit testing

| Option | Default | Description |
| --- | --- | --- |
| `handleSize` | `config.handle.size` (6) | Handle size used for anchoring edges when a `HandleSpec` has no size |
| `edgeInteractionWidth` | `20` | Width of the invisible stroke used to hover and click edges |

## Callbacks

All callbacks are optional. Mouse callbacks receive the DOM `MouseEvent`. On touch screens they receive a `MouseEvent` synthesized from the touch, with `fromTouch: true` set on it.

### Changes

| Callback | Arguments | Fires when |
| --- | --- | --- |
| `onNodesChange` | `(changes: NodeChange[])` | Nodes move, are measured, selected, added, replaced or removed |
| `onEdgesChange` | `(changes: EdgeChange[])` | Edges are selected, added, replaced or removed |
| `onSelectionChange` | `({ nodes, edges })` | The set of selected nodes or edges changes |
| `onInit` | `(controller)` | After the first frame |
| `onError` | `(code: "layout", message)` | A layout algorithm throws or rejects. Without this callback the error propagates. |

### Connections

| Callback | Arguments | Fires when |
| --- | --- | --- |
| `onConnect` | `(connection: Connection)` | A connection ends on a valid handle. When set, the editor does not add the edge itself. |
| `onConnectStart` | `(event, { nodeId, handleId, handleType })` | A connection drag starts |
| `onConnectEnd` | `(event, state: ConnectionState)` | A connection drag ends, valid or not |
| `onClickConnectStart` | `(event, { nodeId, handleId, handleType })` | The first handle of a click connection is clicked |
| `onClickConnectEnd` | `(event, state: ConnectionState)` | The second handle of a click connection is clicked |

`Connection` is `{ source, target, sourceHandle, targetHandle }`, with `null` handles when the handle has no id. A connection started from a target handle is reported source-first.

### Reconnecting edges

| Callback | Arguments | Fires when |
| --- | --- | --- |
| `onReconnect` | `(oldEdge, connection: Connection)` | An edge end is dropped on a valid handle. When set, the editor does not change the edge itself. Without it, the editor calls `controller.reconnectEdge(oldEdge, connection)`. |
| `onReconnectStart` | `(event, edge, handleType)` | An edge end starts moving. `handleType` is the end being moved, `"source"` or `"target"`. |
| `onReconnectEnd` | `(event, edge, handleType, state: ConnectionState)` | The drag ends, valid or not |

Reconnecting does not call `onConnect`, `onConnectStart` or `onConnectEnd`.

### Resizing nodes

| Callback | Arguments | Fires when |
| --- | --- | --- |
| `onNodeResizeStart` | `(event, node)` | A resize control is pressed |
| `onNodeResize` | `(event, node, params: ResizeParams)` | Every pointer move while resizing |
| `onNodeResizeEnd` | `(event, node, params: ResizeParams)` | The control is released. `params` are the last ones `onNodeResize` received. |

`ResizeParams` is `{ x, y, width, height, direction }`. `x` and `y` are the node's `position`, relative to its parent when it has one. `direction` is the sign of the pointer movement on each axis, `[-1 | 0 | 1, -1 | 0 | 1]`.

### Nodes and edges

| Callback | Arguments |
| --- | --- |
| `onNodeClick`, `onNodeDoubleClick` | `(event, node)` |
| `onNodeMouseEnter`, `onNodeMouseLeave` | `(event, node)` |
| `onNodeDragStart`, `onNodeDrag`, `onNodeDragStop` | `(event, node, nodes)`, where `nodes` are all nodes being dragged |
| `onEdgeClick`, `onEdgeDoubleClick` | `(event, edge)` |
| `onEdgeMouseEnter`, `onEdgeMouseLeave` | `(event, edge)` |

### Pane and viewport

| Callback | Arguments | Fires when |
| --- | --- | --- |
| `onPaneClick`, `onPaneDoubleClick` | `(event)` | The background is clicked without dragging |
| `onSelectionStart`, `onSelectionEnd` | `(event)` | A box selection starts or ends |
| `onMoveStart`, `onMoveEnd` | `(viewport)` | A user pan or zoom gesture starts or ends |
| `onMove` | `(viewport)` | The viewport changes for any reason, including controller calls and the minimap |

### Deleting

| Callback | Arguments | Description |
| --- | --- | --- |
| `onBeforeDelete` | `({ nodes, edges })` | Return `false` to cancel, a smaller `{ nodes, edges }` to delete only those, or a promise of either |
| `onNodesDelete` | `(nodes)` | Nodes were deleted |
| `onEdgesDelete` | `(edges)` | Edges were deleted, including those attached to deleted nodes |
| `onDelete` | `({ nodes, edges })` | Anything was deleted |

## Change events

The editor applies every change to its controller first and then reports it. Callbacks are notifications. You never have to apply changes back for the editor to update.

```typescript
type NodeChange =
  | { type: "position"; id: string; position?: XYPosition; dragging?: boolean }
  | { type: "dimensions"; id: string; dimensions: Dimensions; setAttributes?: boolean; resizing?: boolean }
  | { type: "select"; id: string; selected: boolean }
  | { type: "remove"; id: string }
  | { type: "add"; item: FlowNode; index?: number }
  | { type: "replace"; id: string; item: FlowNode };

type EdgeChange =
  | { type: "select"; id: string; selected: boolean }
  | { type: "remove"; id: string }
  | { type: "add"; item: FlowEdge; index?: number }
  | { type: "replace"; id: string; item: FlowEdge };
```

| Source | Changes |
| --- | --- |
| Dragging nodes | `position` with `dragging: true`, then `dragging: false` on release |
| First render and size changes | `dimensions` |
| Resizing a node | `dimensions` with `resizing: true`, then `resizing: false` on release. Resizing from a top or left control adds a `position` change. |
| Clicks, box selection, `selectNodes()` | `select` |
| Delete key, `deleteElements()` | `remove`, edges first |
| Connecting, `addNodes()`, `addEdges()` | `add` |
| `updateNode()`, `updateNodeData()` and the edge equivalents | `replace` |
| Reconnecting an edge, `reconnectEdge()` | `replace` keyed by the old edge id |
| A layout | `position` without `dragging`, plus `dimensions` with `setAttributes: true` for each parent it grew |

Resize changes carry `setAttributes: true`, which writes the new size to `node.width` and `node.height` as well as `measured`. A resized node keeps that fixed size from then on.

To keep your own copy of the graph, for example to save it, apply the changes to that copy:

```typescript
import { applyEdgeChanges, applyNodeChanges } from "flitter-ui/diagram";

FlowDiagram({
  nodes: initialNodes,
  edges: initialEdges,
  onNodesChange: (changes) => {
    store.nodes = applyNodeChanges(changes, store.nodes);
  },
  onEdgesChange: (changes) => {
    store.edges = applyEdgeChanges(changes, store.edges);
  },
});
```

Here `store` is whatever holds your app's data. Two things to avoid:

- Do not feed changes back into the controller, as in `controller.setNodes(applyNodeChanges(changes, controller.nodes))`. They are already applied, and an `add` change would insert the node twice.
- Do not pass a freshly built `nodes` array on every rebuild. Each new identity replaces the editor's nodes. Pass the same array, or drive changes through the [controller](/diagram/api/controller). If you only need a snapshot, `controller.toObject()` returns `{ nodes, edges, viewport }`.

## Graph helpers

These pure functions take and return plain arrays. They work with or without a mounted editor.

| Function | Description |
| --- | --- |
| `applyNodeChanges(changes, nodes)` | Returns a new node array with the changes applied |
| `applyEdgeChanges(changes, edges)` | Returns a new edge array with the changes applied |
| `addEdge(edgeOrConnection, edges)` | Appends an edge unless the same connection exists. Generates an `xy-edge__…` id when none is given. |
| `reconnectEdge(oldEdge, connection, edges, { shouldReplaceId })` | Replaces an edge's endpoints. `shouldReplaceId` defaults to `true`. |
| `getConnectedEdges(nodes, edges)` | Edges touching any of `nodes` |
| `getIncomers(node, nodes, edges)` | Nodes with an edge into `node` |
| `getOutgoers(node, nodes, edges)` | Nodes `node` has an edge to |
