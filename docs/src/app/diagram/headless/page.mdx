# Headless Flow

`Flow` is the headless widget at the centre of every diagram. It owns graph state, measurement, gestures and scene composition. You provide the visual builders and choose the layout. The copied `FlowDiagram` starter is one consumer of this same public API.

The example below imports only `flitter-ui` widgets and `flitter-ui/diagram`. Its own builders draw the nodes, edges, handles, background and selection. Its config is just `{ paper, ink, accent }`.

## The composition boundary

```typescript
import { Flow, circularLayout, type FlowCustom } from "flitter-ui/diagram";

type OrbitTheme = { paper: string; ink: string; accent: string };

// Define all visual builders in your own module, as in the example above.
import { orbitParts } from "./orbit-parts";

const custom: FlowCustom<OrbitTheme> = orbitParts;

export const diagram = Flow<OrbitTheme>({
  nodes: [],
  edges: [],
  config: { paper: "#f2efd8", ink: "#253d2d", accent: "#b5d56a" },
  custom,
  layout: circularLayout,
});
```

`FlowCustom<T>` describes the builder contracts, not a set of visual presets. `T` is whatever your builders need. `Flow` passes it through unchanged.

- Supply all `custom` slots. Optional visuals such as the background and edge labels may return `null` where the contract allows it.
- `nodeTypes` and `edgeTypes` are your maps. No xyflow types are registered for you.
- Add your own `panels` and toolbars. `Flow` does not insert controls or a minimap.
- Use the controller and callbacks for application actions and persistence. The interaction engine is the same as in the starter.

The circular layout and straight paths in the example are choices made by its source. Replace them with another algorithm or your own `compute()` function. See [Layouts](/diagram/api/layout).

## Reuse as much of the starter as you want

You can also compose `Flow` with selected copied parts. Those parts still expect their own config type:

```typescript
import { Flow } from "flitter-ui/diagram";
import {
  createXyflowConfig, xyflowCustom, xyflowNodeTypes, xyflowEdgeTypes,
} from "@/components/diagram/flow-diagram";

export const diagram = Flow({
  nodes: [],
  edges: [],
  config: createXyflowConfig(),
  custom: { ...xyflowCustom, background: () => null },
  nodeTypes: xyflowNodeTypes,
  edgeTypes: xyflowEdgeTypes,
});
```

This reuses the starter's builders without adding its controls and minimap. Edit any of those imported files in your project. If you keep `XyflowControls` or `XyflowMiniMap`, keep the config fields they consume as well.

## What the engine still requires

Visual freedom works within a small set of contracts: return Flitter widgets, declare handles, and supply edge paths with geometry for hit testing. For custom routes, the returned `EdgePathResult` includes drawing commands, a sampled polyline and a label anchor. The engine derives bounds from that geometry. Do not draw a different route without updating its geometry.

Node and edge builders receive interaction flags, and their context exposes controller operations. Drawing a different card does not require another drag implementation. [Builders & Context](/diagram/api) documents these contracts; the [gallery](/diagram/gallery) shows how to use them.
