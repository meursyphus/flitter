# Quick Start

Start with a basic editor, then replace its visual parts. For a workflow, organization chart or another complete composition, you can also start from the [gallery](/diagram/gallery).

## 1. Copy the starter

```bash
npm install @flitterjs/react
npx flitter-ui init
npx flitter-ui add flow-diagram
```

This installs the headless engine and copies the xyflow style into `@/components/diagram/flow-diagram`. `index.ts` assembles the editor, `parts/` contains its widgets and `config.ts` holds that style's defaults. All copied files are yours to edit. See [Installation](/diagram/installation) for aliases and Svelte.

## 2. Describe the graph and mount it

```tsx
import Widget from "@flitterjs/react";
import type { FlowEdge, FlowNode } from "flitter-ui/diagram";
import { FlowDiagram } from "@/components/diagram/flow-diagram";

const nodes: FlowNode[] = [
  { id: "draft", type: "input", position: { x: 0, y: 0 }, data: { label: "Draft" } },
  { id: "review", position: { x: 0, y: 120 }, data: { label: "Review" } },
  { id: "publish", type: "output", position: { x: 0, y: 240 }, data: { label: "Publish" } },
];
const edges: FlowEdge[] = [
  { id: "a", source: "draft", target: "review" },
  { id: "b", source: "review", target: "publish" },
];

const diagram = FlowDiagram({ nodes, edges, fitView: true });

export default function App() {
  return <Widget widget={diagram} width="100%" height="480px" renderer="svg" />;
}
```

The starter draws `data.label` in simple boxes. Its input nodes have a bottom source handle, output nodes a top target handle, and default nodes both. These are definitions in your copied `parts/node.ts`.

Drag nodes, connect handles and zoom the view. The headless engine handles these interactions. Keep the widget instance and input arrays stable: a new adapter widget remounts the editor, and a new nodes/edges array identity replaces that controller data.

## 3. Make the node your own

Replace the starter's `default` type with a widget composition. Add these imports, then replace the `diagram` declaration above:

```typescript
import { Border, BoxDecoration, Container, EdgeInsets, Text, TextStyle } from "flitter-ui";

const diagram = FlowDiagram({
  nodes, edges, fitView: true,
  nodeTypes: {
    default: {
      build: ({ node, selected }) => Container({
        padding: EdgeInsets.all(20),
        decoration: new BoxDecoration({
          color: "#fff7ed",
          border: Border.all({ color: selected ? "#c2410c" : "#fed7aa", width: 2 }),
        }),
        child: Text(String(node.data.label), {
          style: new TextStyle({ color: "#9a3412", fontSize: 16 }),
        }),
      }),
      handles: [{ type: "target", position: "top" }, { type: "source", position: "bottom" }],
    },
  },
});
```

The Review node now uses your widget. Draft and Publish still use the input/output builders. Add a named type for a different kind of content, replace more type entries, or edit the copied builder itself. The [workflow example](/diagram/gallery/workflow) combines title, status, detail and an action in a custom task type.

The same approach applies to edges, labels, handles, backgrounds and panels. [Customization](/diagram/customization) maps each part to its source. [Builders & Context](/diagram/api) describes the arguments available to your code.

## 4. Change the arrangement

A layout places measured nodes without deciding what their widgets look like. For example, add `layout: treeLayout` with an import from `flitter-ui/diagram`. Use an algorithm configuration for another direction or supply your own `LayoutAlgorithm`.

Explore complete combinations:

- [Deployment workflow](/diagram/gallery/workflow): layered layout with horizontal ports and status cards
- [People and teams](/diagram/gallery/organization): tree layout with avatar nodes
- [Service traffic](/diagram/gallery/service-map): force layout with data-driven edge drawing
- [Grouped pipeline](/diagram/gallery/grouped-pipeline): explicit positions inside custom containers
- [Resource board](/diagram/gallery/card-grid): a grid of cards without edges
- [A style from scratch](/diagram/gallery/headless): circular layout and an independent set of headless builders

## 5. Connect your application

The editor keeps the graph in a `FlowController`. Change callbacks report updates after the controller has applied them. Use them to persist or mirror data; do not apply them back to the same controller.

Without `onConnect`, the engine adds an edge after a valid connection. When you provide `onConnect`, your handler owns adding it. A controller also lets your own toolbar or panel update nodes, run layouts and save `{ nodes, edges, viewport }`.

See [Controller](/diagram/api/controller) for lifecycle and state management, and the [workflow source](/diagram/gallery/workflow) for an action that updates a task through its builder context.
